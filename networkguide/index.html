How does a Network work?
The basics, made simple.

Every message online is broken into packets, addressed, and passed hand-to-hand across devices. Learn the few core ideas and networking stops being alphabet soup.

The OSI model — a 7-layer cake

You will be able to
  • Name the seven OSI layers and what lives at each.
  • Explain encapsulation.

Networking is split into 7 layers, each with one job. Your data travels down the stack on the way out and back up on the way in — and each layer only talks to its match on the other end.

✉️ Like mailing a letter: you write the note (top layer), put it in an envelope with an address, the post office sorts it, trucks and planes carry it, and at the far end it's all undone in reverse until your friend reads the note. Each step wraps the message in a little more handling info, then unwraps it at the other end. That wrapping is called encapsulation.
🧠Mnemonics help. Top-down (7→1): "All People Seem To Need Data Processing." Bottom-up (1→7): "Please Do Not Throw Sausage Pizza Away."
📦The data changes names as it goes down: it's called Data up top, a Segment at Transport, a Packet at Network, a Frame at Data Link, and raw Bits at Physical.

What lives at each layer

LayerExample protocol/device
7 — ApplicationHTTP, DNS, the app itself
6 — PresentationEncryption (TLS), compression, character encoding
5 — SessionKeeping a login session alive across requests
4 — TransportTCP, UDP — covered in depth on the TCP/UDP tab
3 — NetworkIP addressing, routers
2 — Data LinkMAC addressing, switches
1 — PhysicalCables, radio waves, actual voltage on a wire

Knowing the layer a problem lives at tells you where to actually look: "the page won't load" could be Layer 7 (the app is down), Layer 3 (no route to the server), or Layer 1 (the cable's unplugged) — and the fix is completely different depending on which.

Two addresses: MAC and IP

You will be able to
  • Tell a MAC address from an IP address.
  • Say what ARP does.

Every device has two addresses that do different jobs — one permanent and local, one changeable and global. You need both to move data across the internet.

🏠 Think of your identity: your MAC address is like your fingerprint — set at the factory (though phones can now randomize it), unique to the hardware. Your IP address is like your mailing address — it depends on where you are and changes when you move networks. The internet uses the IP to find the right neighborhood, and the MAC to hand it to the exact device.
🔖
MAC address
Layer 2 · burned into the hardware

A 48-bit number written as 12 hex digits, like C8:5B:76:62:35:37. The first half identifies the manufacturer (the OUI); the second half is the specific device. It is set at the factory, but phones randomize it for each network and it can be spoofed, so it is a label and not proof of identity. It only matters on the local network.

All ones — FF:FF:FF:FF:FF:FF — is the broadcast address: "everyone on this segment."

📍
IP address
Layer 3 · depends on the network

IPv4 is four numbers 0–255, like 192.168.1.50 — 32 bits total. It's split into a network part (which neighborhood) and a host part (which house). Routers use it to steer packets across the world.

Some ranges are private and only used inside local networks; 127.0.0.1 always means "this device."

Private IP ranges — the addresses behind every router

RangeLegacy class (CIDR)Typical Use
10.0.0.0 – 10.255.255.255Class A (10.0.0.0/8)Large corporate/military networks
172.16.0.0 – 172.31.255.255Class B (172.16.0.0/12)Medium-sized networks
192.168.0.0 – 192.168.255.255Class C (192.168.0.0/16)Home and small office routers
🌍We ran out of IPv4. With only ~4.3 billion addresses, the world outgrew IPv4. IPv6 uses 128 bits — written as 8 groups of hex digits like 2001:0db8:85a3::8a2e:0370:7334 — enough for an almost unimaginable number of devices.

How MAC and IP actually connect: ARP

A device knows the destination IP address, but Layer 2 needs a MAC address to actually deliver a frame on the local network. ARP (Address Resolution Protocol) is the "who has this IP?" broadcast that solves that gap — a device shouts the question to everyone on the segment, and whoever owns that IP replies with its MAC address. That answer gets cached briefly so the same question doesn't need repeating for every packet.

🔁TTL stops loops. Each packet carries a "time to live" that drops by one at every router. Hit zero and it's discarded — so a mis-routed packet can't circle forever.

Subnetting — slicing up address space

You will be able to
  • Work out usable hosts from a CIDR mask.
  • Convert a mask to a CIDR number.

Subnetting decides how an IP address splits into "network" and "host" parts. Get it right and devices can talk; get it wrong and they can't — even sitting next to each other.

🏢 Like a street address: "1600 Pennsylvania Ave" has a street part (the network) and a house number (the host). The subnet mask is the line that says "everything up to here is the street, the rest is the house." Two devices can only talk directly if they're on the same street.

The mask is just a dividing line

A mask like /24 means "the first 24 bits are the network, the last 8 are hosts." More network bits = more separate networks, each with fewer hosts. Fewer = bigger networks. It's a trade you tune with the slash number (CIDR).

Building the mask, bit by bit

A /24 mask means the first 24 bits are all turned ON (1), and the rest are OFF (0). Here's the first octet worth of that idea for a /24 — all 8 bits ON, since 24 ≥ 8:

Each full octet of ON bits equals 255; a fully OFF octet equals 0. That's why a /24 mask is written 255.255.255.0 — three full octets ON, the last fully OFF.

Try it: move the dividing line

Notice the trade: slide toward /30 and you get lots of tiny networks; toward /8 and you get a few huge ones.

Going backwards — from a mask back to a CIDR

Given a subnet mask like 255.255.255.192, count the ON bits: 255.255.255 is 24 full bits, and 192 in binary is 11000000 — 2 more ON bits. Total: 24 + 2 = /26.

➖Why "minus 2"? Usable hosts = 2^(host bits) − 2. Two addresses are reserved in every subnet: the first (the network ID) and the last (the broadcast).
🚫Different subnet = no direct chat. 192.168.1.10 and 192.168.2.10 with a /24 mask are on different networks — they can't talk directly without a router, no matter how close they are.

Worked example: how many hosts fit?

A /26 network leaves 6 bits for hosts (32 − 26 = 6). The number of addresses is 2⁶ = 64 — but two are always reserved (the network address itself, and the broadcast address), leaving 62 usable host addresses. That same math — 2^(host bits) − 2 — works for any mask size.

DHCP — how your device gets an IP address automatically

You will be able to
  • List the four steps of DORA.
  • Say what DHCP hands out besides an address.

You almost never type in an IP address by hand. DHCP is the process quietly running in the background every time a device joins a network, handing out an address automatically.

🏨 Like checking into a hotel: you don't pick your own room number — the front desk assigns you one for your stay, and takes it back when you check out. DHCP does the same thing with IP addresses: it "leases" you one for a limited time, not forever.

The DORA process

1
Discover
Your device broadcasts: "Is there a DHCP server out there? I need an address."
2
Offer
A DHCP server responds: "Here's an available address you can use."
3
Request
Your device replies: "I'll take that one, please" (broadcast so other servers know to stand down).
4
Acknowledge
The server confirms: "It's yours" — and your device configures itself with that address.

Remember it with DORA: Discover, Offer, Request, Acknowledge.

What DHCP hands you besides just an IP

ItemWhat It's For
IP addressYour device's address on this network
Subnet maskTells your device which addresses are "local"
Default gatewayThe router to send traffic to for anything outside the local network
DNS serverWhere to ask when translating names like google.com into an IP
Lease timeHow long you get to keep this address before renewing
⏳Leases expire. If your device stays connected, it quietly renews its lease before it runs out. If it disconnects for a long time, the address can be handed to someone else — which is why your IP sometimes changes after being off the network a while.
🛠️Static vs. dynamic. Most devices use DHCP (dynamic) and just get whatever's available. Servers and network gear often use a fixed, manually configured "static" address instead, so their address never changes.
🚨A rogue DHCP server is a real attack. Because the DORA process trusts whoever answers first, a rogue server on the network can hand out its own gateway/DNS answers instead — quietly routing a victim's traffic through an attacker-controlled path. It's exactly why "which device is answering DHCP requests" matters on a network you're securing.

TCP vs. UDP, and what ports are for

You will be able to
  • Compare TCP and UDP.
  • Name the three-way handshake and common ports.

Getting a packet to the right device (via IP) is only half the job — it also has to reach the right program on that device. That's what ports and transport protocols handle.

🏢 Like an apartment building: the IP address gets your mail to the right building. The port number is the apartment number that gets it to the right resident inside. Two different apartments (ports) in the same building (IP) can be having completely separate conversations at the same time.

TCP vs. UDP — reliable vs. fast

TCPUDP
StyleConnection-based — sets up a link firstConnectionless — just sends it
ReliabilityConfirms delivery, resends lost dataNo confirmation, no resending
SpeedSlower (overhead from reliability checks)Faster (no waiting for confirmations)
Good forWeb pages, email, file transfers — accuracy mattersVideo calls, live streaming, gaming — speed matters more than a perfect copy

TCP's "three-way handshake" — how a connection starts

1
SYN
Your device: "I'd like to start a conversation" (synchronize)
2
SYN-ACK
The server: "Got it, and same to you" (synchronize-acknowledge)
3
ACK
Your device: "Confirmed, let's go" (acknowledge) — the connection is now open

Only after all three steps does actual data start flowing — this is why TCP has more setup delay than UDP, which skips the handshake entirely.

DNS — the internet's phone book

You will be able to
  • Describe how a DNS lookup happens.
  • Break down a URL.

Computers navigate by IP address, but humans remember names. DNS (Domain Name System) is the translation layer that connects the two.

📞 Like an old phone book: you know your friend's name, not their phone number. You look up the name, get the number, then dial. DNS does the same thing: you type a name, it finds the IP address, then your device connects to that address.

How a DNS lookup happens

1
You type a name
e.g., www.example.com, into your browser
2
Your device asks a DNS server
"What's the IP address for this name?"
3
The DNS server responds
With the matching IP address (or points you to another server that knows)
4
Your device connects
Directly to that IP address — the name was just a lookup step

Anatomy of a URL

https://www.example.com/training/lesson1?id=42
Protocol — how to talk (HTTPS = encrypted web traffic) Host — which server, resolved via DNS Path — which specific page/resource on that server Query — extra parameters passed to the page
💾DNS caching speeds things up. Once your device (or its network) looks up a name, it remembers the answer for a while instead of asking again every time — that's why the second visit to a site is often faster to connect than the first.
🚨DNS spoofing exploits that trust. If an attacker can answer a DNS query before the real server does, they can hand back a false IP address — quietly redirecting a device to the wrong destination while it thinks it reached the real one. Same underlying weakness as the rogue DHCP server on the previous tab: whoever answers first, wins.
🔒HTTP vs. HTTPS. The "S" means the connection is encrypted — anyone intercepting the traffic sees scrambled data instead of readable content. Always prefer HTTPS when it's available.

Topologies — how devices are wired together

You will be able to
  • Compare bus, ring, star, and mesh topologies.
  • Name the network sizes.

"Topology" just means the shape of the connections. The shape decides speed, reliability, and what happens when a link breaks.

🛣️ Like road layouts: a single main road everyone shares (bus), a roundabout (ring), spokes into one hub (star), or a web of streets with many routes (mesh). Each layout handles traffic — and road closures — differently.
TopologyShapeIf a link breaks
BusAll on one shared cableA break can down the whole line (old, rarely used now)
RingEach device links to two neighbors in a loopOne break can split the ring
StarEveryone connects to a central switchOne cable failing only drops that device (very common)
MeshMany devices interconnect with multiple pathsTraffic reroutes around the break (most resilient)

Networks come in sizes — and your message travels through all of them

SizeCoversExample
PANYour immediate personal gearPhone to earbuds via Bluetooth
LANA single building or siteYour office or home network
MANA cityA university connecting several campuses
WANRegions or the whole globeThe internet itself — the biggest WAN there is

A message you send often crosses all four in sequence: it starts on your device's PAN, hits your LAN's switch and router, travels across MAN/WAN infrastructure — often over fiber-optic cable for the long-haul legs — and arrives at a server that's doing the same journey in reverse.

💡Fiber carries the long-haul traffic. Once data leaves your building, it's likely traveling as pulses of light through fiber-optic cable for at least part of the journey — light in glass is what makes MAN/WAN-scale distances practical at high speed.
🔀Mesh is why the internet survives. With many possible paths between points, losing one node or link just reroutes traffic — there's no single point of failure. It's also how tactical mesh radios stay connected.

Router

The gear that moves your data

You will be able to
  • Say what switches, routers, and access points do.
  • Tell CSMA/CD from CSMA/CA.

A handful of boxes do the actual work of a network. Here's what each one is for, from dumbest to smartest.

🔀
Switch
Layer 2 · connects a local network

Connects devices within one network and is smart about it — it learns each device's MAC address and sends frames only to the right port, not to everyone. This is the heart of a modern star network.

🌐
Router
Layer 3 · connects networks together

Connects different networks and steers packets between them using IP addresses. Your home router is also the gateway to the internet. If a destination isn't local, your device hands the packet to the router.

📡
Access point (AP)
the wireless on-ramp

Bridges Wi-Fi devices onto the wired network. Its name you see is the SSID; its hardware address is the BSSID.

🤝How devices avoid talking over each other: older shared-cable Ethernet used CSMA/CD (detect collisions) and modern switched, full-duplex Ethernet no longer needs it, while Wi-Fi uses CSMA/CA (avoid them) — because a wireless device can't reliably hear a collision while it's transmitting.
🧭The journey of a click: your device → switch → router → across many routers on the internet → the server, and all the way back — usually in well under a second.

Routing, NAT, and troubleshooting

You will be able to
  • Say how a router picks a route and what NAT does.
  • Size subnets and use ping and traceroute.

Getting a packet across many networks takes a router, a translation trick for private addresses, and a few tools for finding out what went wrong.

🚌 Like a post office sorting hub: each router looks at the destination, picks the best next stop from its table, and passes the packet on. No router knows the whole route, only the next hop.

How a router decides

A router keeps a routing table: a list of destination networks and the next hop for each. When a packet arrives, it picks the entry with the longest matching prefix, the most specific route that fits. If nothing matches, it uses the default route (0.0.0.0/0), usually toward the internet.

NAT: many devices, one public address

🔄Network address translation. Home and office networks use private addresses. The router rewrites each outgoing packet to use its one public address and remembers the port number it used, so replies find their way back to the right device. It also means outsiders cannot start a connection to an inside device unless the router is told to allow it.

Right-sizing subnets (VLSM)

Variable-length subnet masks let you give each network just the size it needs instead of one size for all. Usable hosts = 2host bits − 2.

NeedSmallest fitUsable hosts
Up to 60 devices/2662
Up to 30 devices/2730
A link between two routers/302

Tools for finding the problem

📶ping sends a small test message (ICMP echo) and times the reply. It tells you whether a host is reachable and how long the round trip takes.
🛣️traceroute lists every router along the path. It sends packets with a TTL of 1, then 2, then 3. Each router that drops one because the TTL ran out reports back, so you see each hop in turn.
🔍Packet capture (Wireshark, tcpdump) records the packets on a link so you can read their headers. Encrypted contents stay scrambled. Capture only on networks you are authorized to monitor.

When the trust is abused

🚨ARP spoofing. ARP trusts whoever answers. An attacker on the same local network can reply that the router’s IP belongs to the attacker’s MAC, so traffic flows through the attacker first. It is the same weakness as a rogue DHCP server or DNS spoofing: whoever answers first wins. Switch security features and encryption (HTTPS) limit the damage.
