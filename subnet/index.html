What is a subnet?

Let's start with the big picture — and a really familiar analogy.

🏙️ The internet is like a giant city
🏡 Think of it this way
Imagine a city with millions of houses. Every house has a unique address so mail can find it. The internet works exactly the same — every computer, phone, and smart device needs a unique address (called an IP address) so information can find the right machine.

But cities have a problem: if every street-level decision had to go through city hall, it would be chaos. So cities are broken into neighborhoods. Networking does the same thing with subnets — subnetworks.

🔍 What exactly is a subnet?

A subnet (short for subnetwork) is a logical group of devices that share the same portion of an IP address. Devices on the same subnet can communicate with each other directly and quickly — no detours through a router.

🚀 Without subnets
Every message would be like shouting in a stadium — everyone hears everything. With billions of devices, this would grind the internet to a halt.
✅ With subnets
Devices talk directly within their group. Only messages meant for the outside world leave the subnet — like only going to the post office for out-of-town mail.
🏘️ Why subnets matter
1
Speed: Devices on the same subnet communicate directly through a switch — no router needed. This is much faster, like talking to your neighbor vs. sending a letter through the post office.
2
Security: Subnets act like walls. Your home network can be separated from your work devices. A hospital might keep patient records on a separate subnet from the guest Wi-Fi.
3
Organization: Just like sorting mail by ZIP code makes delivery faster, subnets group devices so network traffic is predictable and manageable.
4
Efficiency: Broadcast messages (sent to all devices at once) only travel within a subnet — not across the whole network. This prevents traffic jams.

IP addresses

Every device gets a unique address — here's how to read one.

📬 What is an IP address?
🏠 Real life
An IP address is like a home address: 123 Oak Street, Springfield, 62701. It uniquely identifies where something lives so messages can be routed there correctly.

IP stands for Internet Protocol. An IPv4 address is four numbers (called octets) separated by dots. Each number ranges from 0 to 255.

🔢 Why 0–255?

Each octet is stored as 8 bits (a bit is either a 0 or a 1). 8 bits can represent 256 different values — from 0 to 255.

All four octets together = 32 bits = about 4.3 billion unique addresses.

🏷️ Special addresses inside a subnet
🚪 Network address (first)
The very first address in a subnet. It identifies the subnet itself — not a device. It's like the street sign at the entrance of a road. You can't "live" at the street sign.
📢 Broadcast address (last)
The very last address. Any message sent here is delivered to every single device on the subnet. Like a loudspeaker announcement for the whole neighborhood.
💻 Usable host addresses (everything in between)
All addresses between the network address and broadcast address can be assigned to real devices — computers, phones, printers, cameras, smart bulbs, and more.
🌍 IPv4 vs IPv6

We're running out of IPv4 addresses! With billions of devices, 4.3 billion isn't enough. IPv6 was invented to solve this.

IPv4 — the classic
192.168.1.50

32 bits, ~4.3 billion addresses. Used everywhere but nearly exhausted.
IPv6 — the future
2001:db8::1

128 bits. Enough addresses for every grain of sand on every beach on Earth — many times over.

The subnet mask

How your computer knows which part of an IP is the "street" and which is the "house number."

🎭 What is a subnet mask?
🔦 Think of it like a highlighter
Imagine an address written on paper. A subnet mask is like using a blue highlighter on the "street" part and a green highlighter on the "house number" part. Without the highlights, you'd have to guess where one ends and the other begins.

A subnet mask is always 32 bits, just like an IP address. It uses 255 (all ones in binary) to mark the network part, and 0 (all zeros) to mark the host part.

So with this mask, 192.168.1 is the neighborhood name — any device with 192.168.1.X is on the same subnet. The .50 is the individual house number.
⚙️ How it works — the AND operation

To find out what subnet an IP belongs to, your computer does a bitwise AND between the IP and the mask. It's simpler than it sounds:

1
For every "1" bit in the mask → keep the matching IP bit. This is the network part.
0
For every "0" bit in the mask → force that IP bit to 0. This is the host part.
Result
The result is the network address — the "street name" that all devices on the same subnet share.

CIDR notation

A shorthand way to write subnet information — much faster than the full mask.

📏 What is CIDR?
✏️ A shortcut
Writing "255.255.255.0" every time is tedious. CIDR (Classless Inter-Domain Routing — say it "cider" 🍺) lets you write /24 instead. The number after the slash tells you how many bits are "locked" for the network part.

An IP with CIDR looks like: 192.168.1.0/24

The /24 means 24 bits are locked for the network — leaving 8 bits (32 - 24) free for host addresses. That gives you 2⁸ = 256 addresses, minus 2 reserved = 254 usable.

📊 CIDR reference chart

Network bits (locked)   Host bits (free)

🧮 How to calculate hosts from CIDR
1
Subtract the CIDR number from 32 to get the host bits. For /24: 32 − 24 = 8 host bits.
2
Raise 2 to the power of host bits: 2⁸ = 256 total addresses.
3
Subtract 2 (network address + broadcast address): 256 − 2 = 254 usable host addresses.

What can go on a network?

Almost anything with a network adapter — and here's why each one matters.

🔑 The golden rule
📋 One rule to remember
Any device that needs to send or receive data over a network must have a network adapter (physical or wireless) and be assigned an IP address on the subnet. That's it! If it has an adapter and an address, it belongs.
🧱 Network infrastructure — the skeleton

These devices build the network itself. They usually get the first few IP addresses in a subnet.

DeviceIP needed?RoleWhy it goes on the subnet
📡 Router Yes Gateway to the internet Sits at the edge of the subnet. Usually gets .1 or .254. Everything talks through it to reach the outside world.
🔀 Switch Optional Connects devices in a subnet Forwards data between devices on the same subnet. Basic switches don't need an IP, but managed switches do for configuration.
📶 Access Point (Wi-Fi) Yes Wireless extension of the subnet Gives wireless devices a way to join the same subnet. Needs an IP for management and configuration.
🔥 Firewall Yes Security gatekeeper Sits between subnets or between the network and the internet. Has an IP on each network it connects to.
💻 End user devices

These are the devices people use every day. They get IP addresses from the router via DHCP (automatic) or manual assignment.

DeviceTypical IPHow it joinsWhat it does on the subnet
🖥️ Desktop PC Static or DHCP Ethernet cable or Wi-Fi Sends/receives web traffic, files, print jobs. Often given a static IP so you can always find it.
💻 Laptop DHCP Wi-Fi or Ethernet Moves around, so usually gets a dynamic IP from DHCP each time it connects.
📱 Smartphone / Tablet DHCP Wi-Fi Browses the web, streams media, syncs apps. Gets a temporary IP from the router.
🖨️ Printer Static Ethernet or Wi-Fi Given a fixed IP so computers always know exactly where to send print jobs. A changing IP would break printing.
📺 Smart TV DHCP Wi-Fi or Ethernet Streams video from the internet and may receive media from other devices on the subnet via DLNA/Chromecast.
🏠 Smart home & IoT devices

IoT (Internet of Things) — everyday objects that connect to the network. Security tip: many pros put these on a separate subnet from computers, so a hacked smart bulb can't touch your laptop!

DeviceWhy it needs an IPBest practice
💡 Smart bulb / plug Receives on/off commands and reports status to the hub Put on a separate IoT subnet
🔒 Smart lock / doorbell Sends alerts and video to your phone Separate subnet with strict firewall rules
🌡️ Smart thermostat Receives temperature schedules, reports current temp Separate IoT subnet

🏢 Servers — always-on devices

Servers provide services to other devices. They almost always get static IPs — you can't have your website moving to a new address every day!

Server typeWhat it does on the subnet
🌐 Web server Hosts websites. Needs a static IP (and usually a public IP or port forwarding)
🗂️ File server (NAS) Stores shared files. Other devices connect to it by its fixed IP address
📋 DHCP server Hands out IP addresses to devices that join the network — usually built into the router
🔍 DNS server Translates domain names (google.com) to IP addresses. Needs a fixed IP so devices can always find it
💾 Database server Stores application data. Usually on a private subnet, never directly exposed to the internet

How devices join a network

Step by step — from plugging in to sending your first packet.

🔌 Two ways to get an IP address
🤖 Automatic — DHCP
The device asks the router: "Can I have an address?" The router (DHCP server) picks an available IP and hands it over — usually within milliseconds. This is how your phone joins Wi-Fi.
✍️ Manual — Static IP
A person types in the IP address, subnet mask, gateway, and DNS settings directly. Used for servers and printers that must always have the same address.

🔒 Why some devices can't join (or shouldn't)
!
No network adapter: A device with no network hardware (NIC) physically cannot join. Think of it like a house with no mailbox — the mail carrier has nowhere to deliver.
!
Wrong subnet configuration: If a device is given an IP outside the subnet range, it can't talk to others. Like having a house addressed "99 Oak Street" when all others are on "Main Street."
!
Firewall / VLAN restrictions: Network admins can block certain devices deliberately — like a gated community that requires a key card. IoT devices are often kept in their own restricted subnet for security.
!
IP conflict: Two devices trying to use the same IP address causes chaos — both stop working. DHCP prevents this by tracking which IPs have been handed out. Static IP setups must be managed carefully.
🏷️ MAC address — the physical ID
🪪 Think of it like a serial number
Every network adapter has a MAC address — a permanent, unique ID burned into the hardware at the factory. It looks like: A4:83:E7:2C:11:F0. It never changes, unlike an IP address.

When a device joins a subnet, the router uses its MAC address to remember which IP it gave out (DHCP lease). You can also set up DHCP reservations — telling the router "always give this MAC address the same IP" — giving a device the convenience of DHCP with the reliability of a static IP.
